RDM 0.3.15 tightens credential isolation and fixes redirected HLS streams, checksum races and packaging safeguards. Browser extension: 0.4.11.

## Fixed

- HLS playlists redirected to another directory now resolve relative variants, audio, segments and keys against their final URL.
- Changing or clearing a checksum while an earlier verification is running no longer lets the old result overwrite the current verdict or raise an obsolete mismatch notification.
- A failed completion-marker write for a separate video/audio track now cancels its sibling instead of leaving it downloading.

## Security

- Raw cookies forwarded by the browser stay on their original host. Without their original Domain/hostOnly attributes, sharing them with sibling hosts could expose session cookies. Protected media needing cookies on another host may need to be sent from that host instead.
- Changing a download link filters each credential independently: HTTP authentication stays on its origin, including its port. Secret header names are recognized regardless of case and proxy authorization is excluded from saved history too.
- A separate audio URL accompanying an Internet video cannot point directly into the local network.
- Extension SameSite checks use the full bundled Public Suffix List, including private hosts, wildcard rules and exceptions. Unrelated hosting tenants no longer count as one site for Strict cookies.
- Extension packaging refuses output directories inside repository sources, including `.git`, `crates`, `docs` and `packaging`. Only `target` and `dist` can be replaced inside the checkout.

## Release checks

- A release tag must match the workspace version and have release notes before its build starts.
- A new GitHub release stays a draft until every package and signature has been uploaded.
- Regression coverage includes the plain Safari background worker and the release-version guard.

The audit scope, verification results and remaining limitations are documented in `docs/audit-2026-11-08.md`.
