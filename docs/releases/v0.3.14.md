RDM on ARM (Windows, Linux, and macOS on Apple Silicon, natively on the M1 and every later chip), the Safari extension, the extension offered in the browser itself, and the fixes of a full audit; everything of 0.3.13 too, which never went out. Nothing to do on your side: update as usual.

## Install

| System | File |
|---|---|
| Windows 10 / 11 | **`RDM-0.3.14-x64-setup.msi`**, on ARM **`RDM-0.3.14-arm64-setup.msi`** (its window needs OpenGL: Microsoft's "OpenCL, OpenGL, and Vulkan Compatibility Pack" where the PC lacks it), or let RDM install it by itself (the "Version 0.3.14 available" card) |
| macOS 11 or later, Apple Silicon | **`RDM-0.3.14-macos-arm64.dmg`**: drag RDM to Applications. RDM is not signed by an Apple Developer account: allow its first start in System Settings → Privacy & Security → Open Anyway |
| Debian / Ubuntu | `rdm_0.3.14-1_amd64.deb`, on ARM `rdm_0.3.14-1_arm64.deb`: `sudo apt install ./rdm_*.deb` |
| Fedora / openSUSE | `rdm-0.3.14-1.x86_64.rpm`, on ARM `rdm-0.3.14-1.aarch64.rpm`: `sudo dnf install ./rdm-*.rpm` |
| Linux (others) | `rdm-linux-x64.tar.gz`, on ARM `rdm-linux-arm64.tar.gz`: extract, then `sh install.sh` |
| Chrome / Edge / Brave / Opera / Vivaldi… | from RDM (the "Browser extension" card), or `rdm-chromium.zip` |
| Firefox / Waterfox / LibreWolf… | from RDM, or `rdm-firefox.xpi` (extension 0.4.10) |
| Safari | inside `RDM.app`: from RDM (the "Browser extension" card) |

## New

- **ARM**: native packages for Windows on ARM and Linux ARM64, which update themselves like the others; the YouTube module too.
- **macOS**: the application, its menu bar icon, the browser extension and its connector, the YouTube module, start at login, Gatekeeper's quarantine on downloaded files. Transfers stay on the performance cores, with no App Nap, while RDM sits in the menu bar.
- **Safari**: the extension comes inside `RDM.app`. Without an Apple Developer signature, Safari asks for "Allow unsigned extensions" (its developer settings) each time it opens.
- **The extension offered in the browser**: when you open RDM, in your default browser; then each time you open any browser without the extension. The browser itself asks for your go-ahead. Settings → Browser turns this off.
- **Mini download button** (Settings → Browser): a small icon without text over videos and 3D models. The extension also detects 3D models (glTF/GLB, OBJ, FBX, STL, USD, Gaussian splats, Sketchfab…) and offers to download them.
- **The YouTube module keeps up**: when YouTube refuses its yt-dlp, RDM brings yt-dlp up to date for the next try (at most once a day, its signature checked as at installation). Installed once and never updated, it fell behind YouTube.

## Fixed

- A finished file is on disk before RDM calls it finished: a power cut right after a download could leave a "complete" file with holes in it.
- Two links whose names differ only by case (`A.zip`, `a.zip`) no longer write into one file on Windows.
- A link sent from the browser starts RDM again on Windows, when it was closed: waiting for its port, the connector gave up just before Windows said nothing listened.
- Protected links whose cookies hold accented characters no longer fail with 403: the cookies were dropped.
- A server refusing the `Range` header with an error (403, 416…) still gives the file, on one connection.
- A YouTube recording no longer stops after 2 minutes without data while the player waits (a click to start, an ad break, a slow network).
- Parts of split zip archives (`.z01`, `.z02`…) reach RDM from the browser, as they do from the clipboard.
- HLS: a stream encrypting its initialization section gave a file no player could read.
- Very long names cut right after a dot no longer leave a file Windows names differently.
- A file name a server sends in raw UTF-8 or Latin-1 is kept: the file was named after its link (`download.php`).
- A server answering a range with a partial answer of unknown size still gives the file, on one connection: the download used to end in failure.
- YouTube: a title cut inside an emoji no longer gets the download refused, with "RDM is not running".
- A download starting at the very moment RDM closes is stopped like the others.
- Installing the extension while RDM updates its copy no longer fails with "cannot write the extension".
- A setting of a newer RDM (a category it does not know) no longer resets all the settings.

## Security

- A web page posting to RDM's local port no longer gets up to 32 MB held in memory per request before being refused.
- A server answering far more than the one byte asked for, when RDM asks about a file, is no longer read to its end.
- A finished download no longer keeps its site's cookies in memory.
- The settings no longer say passwords are encrypted on Linux and macOS: they are in a file only your account can read.
- The Windows installer starts RDM by its quoted path: with a space in the account's name, Windows tried `C:\Users\First.exe` first.
- "Change the link": the old link's cookies no longer go to a new link on another site (or in clear), nor an accepted invalid certificate to another host.
- The Windows update assistant runs from a folder of its own: a program looks for its libraries beside itself first, and the temporary folder holds whatever other programs leave there.
- Passwords being saved no longer stay in a temporary file when the save fails.
- HLS: a stream naming one key per segment no longer holds up to 200 MB of them in memory.
- rustls 0.23.46, rustls-webpki 0.103.16, webpki-roots 1.0.11 (RUSTSEC-2026-0346 to 0349, 0381, 0382); zip 9 (RUSTSEC-2026-0367 to 0369); tokio 1.54, clipboard-win 5.4.3 (yanked version replaced).

## Lighter

- Windowless (in the tray), RDM gives back to the system what its window used. On Linux, a download's peak no longer stays in RDM's memory.
- The extension: its button is built only on pages showing it, no longer in every frame of every page; a response's address is read once; a recording copies less.
- A download's data is synced through its open file, without opening it again every 20 seconds (on Windows, an antivirus scan each time).

## Linux

- The packages now run on older distributions: they are built on the oldest supported Ubuntu (22.04).
- The `.rpm` asks for libraries by their own names, not Fedora's package names: it installs on openSUSE too.
- `install.sh --uninstall` removes the connector's registration from every browser RDM found, not only the well-known ones.
- `sudo sh install-ubuntu.sh` goes on as the user, and a build folder left owned by root no longer stops it; on KDE Plasma the menu entry shows at once; notifications are filed under RDM.
